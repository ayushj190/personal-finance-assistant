# Agent Layer

## Overview

The agent layer coordinates the local AI Copilot for the application. It manages local Ollama LLM requests, exposes deterministic financial tools to the model, and runs background inference tasks safely without blocking user interface interactions.

## Key files

| File | Owns |
|---|---|
| `agent/copilot.py` | Copilot turn coordination, system prompt definitions, and tool dispatch mapping |
| `agent/tools.py` | Implementation of native functions called by the LLM and their JSON schema specs |
| `agent/copilot_task.py` | Background thread wrapper handling asynchronous tool calls and token streams |
| `agent/chart_renderer.py` | Construction of Plotly figures dynamically requested during conversational turns |

## Conventions

- Every tool function must return a serializable dictionary containing a `success` boolean and an explanatory message.
- Prefer deterministic service routines in `services/` over LLM token predictions for math and tax calculations.
- Maintain strict typing and parameter documentation in `COPILOT_TOOLS_SCHEMA` for any newly added tool.

## Gotchas

- Copilot tasks execute in independent threads; functions called by the agent must guard against uninitialized `st.session_state` variables.
- Direct database queries generated by the LLM run under an enforced read only SQLite authorizer; schema modifications or writes will be rejected.
